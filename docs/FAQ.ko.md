# 자주 묻는 질문과 문제 해결

> README 의 [시작하기](../README.ko.md#시작하기)에서 이어지는 문서입니다.

## 자주 묻는 질문

**SSD 에 설치한 게임도 되나요?**
아니요. HDD 에 있는 게임만 대상입니다. SSD 에 있는 게임은 필요가 없으므로 건너뜁니다. Windows 가 있는 드라이브가 HDD 이면 그 게임은 발견과 예열만 하고(상태 "prewarm only (system drive)"), 재배치하거나 티어를 두지 않습니다.

**안티치트 게임에서 안전한가요?**
AsterCache 는 게임 프로세스에 손대지 않습니다. 자기 프로세스에서 파일을 읽고, Windows 이벤트 추적으로 파일 읽기를 관찰하며, 게임이 종료된 뒤에만 파일을 옮깁니다. 다만 통제된 검증은 하지 않았습니다. 이 PC 에서 Vanguard 게임(League of Legends)과 Ricochet 게임(Call of Duty)을 설치본으로 플레이한 사용 기록만 있고([이 PC 의 사용 기록](ANTICHEAT.ko.md#이-pc-의-사용-기록)), 계정 제재 여부는 보증하지 않습니다. 안티치트 게임은 플레이 전에 자동 모드를 끄거나 `auto.ignore_exes` 에 넣으십시오. 자세한 내용은 [안티치트 호환](ANTICHEAT.ko.md)을 보십시오.

**RAM 을 얼마나 쓰나요?**
구역 크기만큼입니다. 구역은 게임이 읽는 데이터 묶음이며 기본 상한은 2 GiB 입니다. 예열 뒤에도 가용 RAM 이 4 GB 이상 남을 때만 실행하고, 다른 프로그램이 메모리를 필요로 하면 Windows 가 캐시를 회수합니다.

**게임 업데이트 뒤에는 어떻게 되나요?**
패치로 파일이 바뀌면 저장해 둔 계획과 맞지 않을 수 있습니다. AsterCache 는 옮기기 전에 계획을 확인해 바뀐 파일은 건너뛰고, 게임이 꺼져 있는 동안 5분마다 배치가 흐트러졌는지 보고 흐트러졌으면 계획을 다시 적용합니다. 자동 모드에서는 일부 파일만 바뀌었으면(계획 핫 데이터의 절반 미만) 바뀐 파일의 범위만 학습한 트레이스와 예열 목록에서 빼고(원본은 `.stale` 로 보관) 나머지로 계획을 다시 만들며, 다음 플레이에서 바뀐 파일을 다시 학습합니다. 절반 이상 바뀌었으면 트레이스와 계획 전체를 `.stale` 로 치우고 처음부터 다시 학습합니다. 큰 패치 뒤에는 트레이스 수집, 계획 만들기, 재배치 실행을 다시 하십시오. 실제 게임 업데이트로는 아직 시험하지 않았습니다.

**SMR 인지 CMR 인지가 중요한가요?**
SMR 드라이브(WD20EZAZ) 1대만 측정했고 CMR 은 측정하지 않았습니다. 헤드 이동을 줄이는 것이므로 둘 다 도움이 될 것으로 보지만 검증하지 않았습니다. SMR 은 처음 한 번 옮길 때 쓰기가 느려질 수 있습니다.

**첫 실행이 꼭 필요한가요?**
재배치에는 게임이 실제로 읽는 기록(트레이스)이 필요합니다. 첫 실행에서 기록이 생기기 전에는 공유 프로필(`auto.shared_profiles`)을 먼저 찾고, 그다음 게임의 Windows 프리페치 기록을 봅니다. 프리페치 기록과 공유 프로필은 부트 트레이스가 되어 첫 실행 전에도 재배치를 시작할 수 있습니다. 공유 프로필 저장소(https://github.com/DO0OG/AsterCache-profiles)는 준비 중이라 아직 없으며, 없으면 조용히 건너뜁니다. 기록이 없어도 예열은 합니다. 설치 폴더 전체가 RAM 예산(물리 RAM 의 4분의 1과 가용 RAM 에서 `prewarm.min_free_ram_mib` 을 뺀 값 중 작은 쪽) 이하인 게임은 폴더 전체를 예열하며(`auto.full_prewarm`, 기본 켬, 예산은 `auto.full_prewarm_max_mib` 로 바꿀 수 있습니다), 더 큰 게임은 엔진(Unity, Unreal, Source)을 감지해 로딩 초반에 거의 반드시 읽는 파일만 예열합니다(`auto.engine_profiles`, 기본 켬). 두 예열의 효과는 아직 측정하지 않았습니다. 다른 PC 에서 만든 기록은 `aster profile import` 로 가져올 수 있습니다(`aster profile export` 참고). 가져온 기록은 `plans\<이름>.boot.trace.json` 으로 저장되어 첫 실행 없이도 재배치와 예열이 시작되고, 첫 실행은 그대로 기록되어 그 기록으로 계획을 다시 만들고, 옛 계획은 `.stale` 로 남깁니다(같은 존을 먼저 시도).

**처음 실행도 빨라지나요?**
첫 실행 선행 읽기는 실험 기능이며 기본 꺼짐입니다(E7~E7f 측정에서 이득 없음, `auto.learn.enabled`). 첫 실행은 읽기 기록만 하고, 최대 효과는 재배치와 예열이 끝난 두 번째 실행부터입니다. 런처 라이브러리가 아니라 실행 감지로만 찾은 게임은 그 다음 실행부터 기록을 시작합니다. 측정 과정은 [docs/RESULTS_SUMMARY.ko.md](RESULTS_SUMMARY.ko.md#e7-첫-실행-선행-읽기) 에 있습니다. 예열(폴더 전체 또는 엔진 프로필)은 기록 없이도 돌지만 효과는 아직 측정하지 않았습니다.

**파일이 망가질 수 있나요?**
옮길 때마다 SHA-256 으로 검증하고, 되돌릴 수 있는 저널에 기록합니다. 그래도 실제 데이터를 옮기는 베타이므로 중요한 드라이브는 먼저 백업하십시오. [안전 장치](../README.ko.md#안전-장치)를 보십시오.

## 문제 해결

**설정을 저장할 권한이 없다고 나옵니다.**
데이터 폴더는 관리자만 쓸 수 있습니다. 관리 창을 관리자 권한으로 다시 실행하십시오.

**게임을 추가하거나 제거했는데 반영되지 않습니다.**
서비스는 `config.json` 을 5초마다 다시 읽으므로 보통 다시 시작하지 않아도 반영됩니다. 새 설정이 검증이나 폴더 권한 검사에 실패하면 옛 설정을 유지하고 이유를 로그에 남깁니다.

**트레이에 "서비스 재설치 필요"가 표시됩니다.**
트레이 갱신은 서비스 실행 파일을 바꾸지 않습니다. 설치 프로그램으로 서비스를 다시 설치하십시오.

**재배치 명령이 `not_admin` 으로 끝납니다.**
재배치, 되돌리기, 볼륨 명령은 관리자 PowerShell 에서 실행하십시오.

**예열이 실행되지 않았습니다.**
건너뛴 이유는 `service.log` 에 남습니다. 가용 RAM 이 부족하거나, 게임이 실행 중이거나, 쿨다운 중이거나, 계획 파일이 없는 경우입니다. 게임 실행 여부는 그 게임에 등록된 실행 파일 이름으로만 봅니다. 설치 폴더 아래 미등록 보조 프로세스는 실행으로 치지 않습니다. 건너뜀 로그에는 판정 근거 프로세스 이름과 pid 가 남고, 실행 경과 시간은 서비스가 시작을 관측한 시각부터 셉니다(프로세스 시작 시각은 읽지 않음). `aster status` 의 `prewarm` 항목에서도 확인할 수 있습니다.
