# 자주 묻는 질문과 문제 해결

> 짧게 답하고, 자세한 설명은 해당 문서로 안내합니다. 먼저 README 의 [시작하기](../README.ko.md#시작하기)를 보십시오.

## 자주 묻는 질문

**SSD 에 설치한 게임도 되나요?**
아니요. HDD 에 있는 게임만 대상입니다. SSD 에 있는 게임은 필요가 없으므로 건너뜁니다. Windows 가 있는 드라이브가 HDD 이면 그 게임은 발견과 예열만 하고(상태 "prewarm only (system drive)") 재배치하지 않습니다.

**하드디스크 수명에 나쁜가요?**
재배치는 게임 드라이브에 쓰지만 상한이 있습니다. 한 번에 SMR 드라이브는 최대 1 GiB(그 밖에는 2 GiB), 하루에 SMR 은 2 GiB(그 밖에는 8 GiB)이고, PC 가 한가할 때만 합니다. 그 뒤에는 주로 읽습니다. 드라이브 수명, 온도, 소음에 미치는 영향은 측정하지 않았습니다. [하드디스크에 미치는 영향과 주의사항](../README.ko.md#하드디스크에-미치는-영향과-주의사항)과 [게임 적용 안내](GAME_GUIDE.ko.md)를 보십시오.

**게임을 하는 동안 무엇을 하나요?**
게임이 시작되면 그 게임의 기록된 데이터를 최대 120초 동안 순서대로 읽고(로딩 경계에서 더 일찍 멈춥니다), 같은 디스크의 배경 작업(재배치, 예열, 다른 읽기)은 기다리거나 멈춥니다. 플레이 기록을 위해 게임 파일이나 프로세스가 아니라 디스크의 읽기 카운터를 표본으로 읽습니다. 단계는 [자동 모드](AUTO_MODE.ko.md), 설정은 [설정](CONFIGURATION.ko.md)에 있습니다.

**지우면 어떻게 되나요? 게임을 목록에서 빼면요?**
프로그램을 제거하면 먼저 SSD 보조 저장의 링크를 되돌린 뒤 프로그램과 서비스를 지웁니다. 데이터 폴더 `%ProgramData%\AsterCache` 는 남습니다. 이미 옮긴 조각은 되돌려지지 않으며 어느 쪽이든 파일 내용은 그대로입니다. 예전 배치로 복원하려면 먼저 게임 탭에서 **되돌리기**를 누르십시오. 게임을 목록에서 빼도 파일은 그대로입니다. [사용법](USAGE.ko.md#자주-하는-작업)을 보십시오.

**RAM 을 얼마나 쓰나요?**
예열한 데이터는 일반 파일 캐시입니다. 모든 게임을 합쳐 기본으로 물리 RAM 의 절반 이하이며(`prewarm.max_cache_mib`), 예열 뒤에도 가용 RAM 이 4 GB 이상 남을 때만 실행합니다. 다른 프로그램이 메모리를 필요로 하면 Windows 가 캐시를 회수합니다. [설정](CONFIGURATION.ko.md)을 보십시오.

**안티치트 게임에서 안전한가요?**
AsterCache 는 게임 프로세스에 손대지 않습니다. 자기 프로세스에서 파일을 읽고, Windows 이벤트 추적으로 파일 읽기를 관찰하며, 게임이 종료된 뒤에만 파일을 옮깁니다. 다만 통제된 검증은 하지 않았고 한 PC 의 사용 기록만 있으며, 계정 제재 여부는 보증하지 않습니다. 안티치트 게임은 플레이 전에 자동 모드를 끄거나 `auto.ignore_exes` 에 넣으십시오. [안티치트 호환](ANTICHEAT.ko.md)을 보십시오.

**게임 업데이트 뒤에는 어떻게 되나요?**
패치로 파일이 바뀌면 저장해 둔 계획과 맞지 않을 수 있습니다. AsterCache 는 옮기기 전에 계획을 확인해 바뀐 파일은 건너뛰고, 게임이 꺼져 있는 동안 5분마다 배치가 흐트러졌는지 보고 흐트러졌으면 계획을 다시 적용합니다. 자동 모드에서는 바뀐 파일을 다시 학습하며, 계획 데이터의 절반 이상이 바뀌었으면 트레이스와 계획 전체를 `.stale` 로 치웁니다. 실제 게임 업데이트로는 아직 시험하지 않았습니다. [자동 모드](AUTO_MODE.ko.md)를 보십시오.

**SMR 인지 CMR 인지가 중요한가요?**
SMR 드라이브(WD20EZAZ) 1대만 측정했고 CMR 은 측정하지 않았습니다. 헤드 이동을 줄이는 것이므로 둘 다 도움이 될 것으로 보지만 검증하지 않았습니다. SMR 은 처음 한 번 옮길 때 쓰기가 느려질 수 있습니다.

**첫 실행이 꼭 필요한가요?**
재배치에는 게임이 실제로 읽는 기록(트레이스)이 필요합니다. 첫 실행 전에는 맞는 공유 프로필(저장소가 준비 중이라 지금은 건너뜁니다)을 먼저 찾고, 그다음 게임의 Windows 프리페치 기록을 봅니다. 둘 다 부트 트레이스가 되어 재배치를 일찍 시작할 수 있습니다. 예열은 기록이 없어도 합니다. 설치 폴더 전체가 RAM 예산 안인 게임은 폴더 전체를, 더 큰 게임은 엔진의 파일만 예열하며, 효과는 아직 측정하지 않았습니다. 다른 PC 에서 만든 기록은 `aster profile import` 로 가져올 수 있습니다([사용법](USAGE.ko.md#aster-명령)).

**처음 실행도 빨라지나요?**
아니요. 첫 실행은 읽기 기록만 하고, 최대 효과는 재배치와 예열이 끝난 두 번째 실행부터입니다. 첫 실행 선행 읽기는 실험 기능이며, E7~E7f 측정에서 이득이 없어 기본 꺼짐입니다(`auto.learn.enabled`, [RESULTS_SUMMARY](RESULTS_SUMMARY.ko.md) 참고).

**Wallpaper Engine 처럼 계속 켜져 있는 프로그램도 최적화하나요?**
아니요. 게임이 아니고 한 번 띄우면 계속 켜져 있는 데스크톱 유틸리티(Wallpaper Engine, YoloMouse, Lossless Scaling, OBS Studio, SteamVR 등)는 자동 등록에서 제외하며, 이미 등록된 항목은 서비스가 시작된 뒤 한 번 등록 해제합니다. 그 밖의 프로그램은 게임 탭에서 제거하면 다시 등록되지 않습니다.

**파일이 망가질 수 있나요?**
옮길 때마다 SHA-256 으로 검증하고, 되돌릴 수 있는 저널에 기록합니다. 그래도 실제 데이터를 옮기는 베타이므로 중요한 드라이브는 먼저 백업하십시오. [안전 장치](DEVELOPMENT.ko.md#안전-장치)를 보십시오.

## 문제 해결

**설정을 저장할 권한이 없다고 나옵니다.**
데이터 폴더는 관리자만 쓸 수 있습니다. 관리 창을 관리자 권한으로 다시 실행하십시오.

**게임을 추가하거나 제거했는데 반영되지 않습니다.**
서비스는 `config.json` 을 5초마다 다시 읽으므로 보통 다시 시작하지 않아도 반영됩니다. 새 설정이 검증에 실패하면 옛 설정을 유지하고 이유를 `service.log` 에 남깁니다.

**트레이에 "서비스 재설치 필요"가 표시됩니다.**
트레이 갱신은 서비스 실행 파일을 바꾸지 않습니다. 설치 프로그램으로 서비스를 다시 설치하십시오.

**재배치 명령이 `not_admin` 으로 끝납니다.**
재배치, 되돌리기, 볼륨 명령은 관리자 PowerShell 에서 실행하십시오.

**예열이 실행되지 않았습니다.**
건너뛴 이유는 `service.log` 에 남습니다. 가용 RAM 이 부족하거나, 게임이 실행 중이거나, 쿨다운 중이거나, 계획 파일이 없는 경우입니다. 게임 실행 여부는 그 게임에 등록된 실행 파일 이름으로만 봅니다. `aster status` 의 `prewarm` 항목에서도 확인할 수 있습니다.
