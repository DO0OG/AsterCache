# 사용법

> 트레이 창과 `aster` 명령의 사용법을 예시와 함께 설명합니다. 설치하고 나면 [자동 모드](AUTO_MODE.ko.md)가 각 단계를 자동으로 진행합니다. 이 문서는 상태를 보고, 설정을 바꾸고, 단계를 직접 실행할 때 보는 문서입니다. 이 문서에서 재배치는 게임이 로딩 때 읽는 데이터(핫 데이터)를 같은 드라이브의 한 연속 영역(존)으로 옮기는 것이고, 예열은 그 데이터를 미리 RAM 의 파일 캐시로 읽어 두는 것입니다.

## 평소 사용

- **할 일은 없습니다.** 설치한 뒤 평소처럼 게임을 하면 됩니다([시작하기](../README.ko.md#시작하기) 참고).
- **창 열기.** 트레이 아이콘을 두 번 누르거나 바탕화면 바로가기를 씁니다. 창을 닫으면 앱은 트레이로 돌아갑니다.
- **관리자 권한.** 설정 저장, 트레이스 수집, 재배치, 되돌리기, 서비스 제어에 필요합니다. 없으면 위쪽에 안내 띠와 **관리자로 다시 실행** 버튼이 나타납니다. Program Files 아래에 설치하면 로그온 예약 작업이 트레이를 관리자 권한으로 시작하므로 확인 창(UAC)이 뜨지 않습니다.

## 관리 창

왼쪽에는 고정 드라이브 목록(문자, 레이블, HDD/SSD, 여유 공간, 등록된 게임 수)이 있습니다. 하나를 고르면 그 드라이브의 게임만 보입니다.

| 탭 | 할 수 있는 일 |
|---|---|
| **상태** | 서비스 상태와 마지막 예열, **자동 진행** 숫자 타일 다섯 개(찾은 게임, 만든 계획, 재배치, 예열, 평균 적중률), 게임별 카드(단계, 배치 판정, 마지막 재배치, 예열 결과, `예열 직후 적중 N%`, 마지막 플레이)를 봅니다. 마지막 플레이는 두 줄로, 언제 플레이했는지와 시작할 때의 예열 상태, 처음 30초·처음 120초·플레이 전체의 디스크 읽기 통계를 보여 줍니다. 플레이는 서비스가 게임 프로세스가 사라진 것을 처음 본 시각에 끝난 것으로 치므로, 종료 시각과 플레이 전체 수치에는 종료를 확정하기 전 60초 대기가 들어가지 않습니다. 이 값은 디스크 읽기 카운터이며 로딩 시간이나 프레임을 잰 값이 아닙니다. 기본값이 아닌 정책이나 일시 중지는 카드에도 표시됩니다. 실행 직후 꺼진 게임은 카드에 "실행 직후 꺼짐 N회, 새 드라이버: ..." 가 표시됩니다([자주 묻는 질문](FAQ.ko.md) 참고). |
| **게임** | 게임별 상태, 예열 상태, 보류 이유, 안티치트 표시를 봅니다. 버튼은 등록, 제거, 게임 설정, 트레이스 수집, 계획 만들기, 재배치 실행, 되돌리기, 지금 예열, 측정, 프로필 내보내기, 프로필 가져오기입니다(아래 참고). **고급 열 보기**를 켜면 경로와 설정이 더 보입니다. 게임을 고른 뒤 **게임 설정**을 누르면 창이 열립니다. 창에는 **일시 중지** 체크 상자, **정책**(`games[].mode`: 전체(기본값), 예열만, 재배치만, 사용 안 함, 각각 한 줄 설명)과 표시 이름 칸 세 개(기본 이름, 한국어 이름, 영어 이름)가 있고, **저장**과 **취소**가 있습니다. 내부 이름은 바뀌지 않습니다. 기본값이 아닌 정책이나 일시 중지는 게임 이름 아래에 "일시 중지됨 · 예열만"처럼 표시됩니다. |
| **설정** | **자동 모드** 카드(자동 모드 사용, 발견, 트레이스, 재배치, SSD 보조 저장, 예열할 최근 게임 수, 제외할 실행 파일, 존 상한, 하루 쓰기 상한), 자동 모드 카드의 **게임 시작 때 미리 읽기 (시작 스트림)** 체크 상자(`auto.start_stream_enabled`, 끄면 게임 시작 때와 실행 중에 그 게임의 예열 캐시를 다시 참조하고 붙드는 일도 하지 않음, [SOLAR](SOLAR.ko.md) 참고), **재배치 시간대**(`auto.relocate_hours`: **언제든**, 또는 **시간 지정**으로 자정을 넘길 수 있는 시작~끝 시각. 한 구간이 아닌 값은 그대로 두고 **사용자 지정 (파일에서 편집)**으로 표시하며, 시작과 끝이 같으면 저장하지 않습니다), **업데이트** 카드(자동 설치, 알림만, 끄기, 프리릴리스 포함, 지금 확인), **알림** 체크 상자, **서비스** 카드(설치, 제거, 시작, 정지), 감시기, **언어**, 데이터·로그 폴더 열기, 트레이·서비스 버전을 다룹니다. 맨 아래 **고급** 구역은 **고급 설정 보기**를 켜야 펼쳐지며 기본으로 접혀 있습니다(아래 설명). |
| **로그** | `service.log` 와 `tray.log` 의 마지막 200줄을 새로 고침과 함께 보여 줍니다. **진단 내보내기**는 고른 위치에 ZIP 파일을 만듭니다([자주 묻는 질문](FAQ.ko.md) 참고). |

**고급 구역 (설정 탭).** `config.json` 에서만 고칠 수 있는 숫자 값을 둡니다. 각 항목은 기본값과 한 줄 설명을 보여 주며, 범위를 벗어난 값은 거절되고 아무것도 저장되지 않습니다. **고급 설정 적용**을 누르면 위 자동 모드의 입력도 함께 한 번에 저장됩니다. 예열 캐시 예산(`prewarm.max_cache_mib`)은 게임마다가 아니라 모든 게임이 함께 쓰며, 0 은 물리 RAM 의 절반입니다. 설정 창에서 바꾸면 등록된 모든 게임에 같은 값을 적습니다(0 이면 키를 지움). 나머지는 서비스 시작 때 예열할 게임 수와 크기 상한(`auto.startup_warm_games`, `auto.startup_warm_max_mib`), 게임이 끝난 뒤 그 게임의 재예열 점검을 돌리기까지의 시간(`auto.rewarm_after_exit_min`, 점검은 캐시가 식었을 때만 다시 읽음), 하루 재배치 횟수(`auto.max_relocations_per_day`), 유휴 판정 시간(`auto.idle_seconds`), 시작 스트림 시간 상한(`auto.start_stream_cap_seconds`)입니다. 모든 키는 [설정](CONFIGURATION.ko.md)에 있습니다.

트레이 아이콘 메뉴에는 **열기**, **지금 예열 (스트림)**, **업데이트 확인**, 새 버전이 준비되면 **업데이트 설치 (버전)**, 그리고 **로그 열기**가 있습니다.

## 자주 하는 작업

**AsterCache 가 무엇을 하는지 보기.** **상태** 탭을 엽니다. 게임 카드에 단계가 나옵니다: 발견 → 트레이스 수집 → 재배치 대기 → 재배치 중 → 완료.

**자동 모드 끄기.** **설정** 탭에서 **자동 모드 사용** 체크를 풀고 **자동 모드 적용**을 누릅니다. 또는 `%ProgramData%\AsterCache\config.json` 에 `"auto": {"enabled": false}` 를 씁니다.

**게임 하나만 빼기.** 그 exe 를 `auto.ignore_exes` 에 넣거나, **게임** 탭에서 게임을 고르고 **제거**를 누릅니다(exe 가 목록에 들어가 다시 등록되지 않습니다).

**게임 일시 중지 또는 허용 범위 줄이기.** **게임** 탭에서 게임을 고르고 **게임 설정**을 누른 뒤 **일시 중지**를 켜거나 끄고 정책을 고릅니다. 일시 중지한 게임과 **사용 안 함** 게임은 새 작업을 시작하지 않으며 트레이스도 하지 않습니다. 이미 진행 중이던 트레이스는 기록한 읽기를 그대로 저장합니다. **예열만**은 예열과 계획만 하고 파일은 옮기지 않습니다. **재배치만**은 옮기기만 하고 예열하지 않습니다. 다른 게임에는 영향이 없습니다.

**게임이 실행하자마자 꺼질 때.** **상태** 탭의 그 게임 카드와 `service.log` 의 `exited quickly`, `quick exit N in a row`, `backing off for this run` 를 보십시오. AsterCache 가 꺼지는 것을 막지는 않으며, 마지막 정상 실행 뒤 새로 올라온 커널 드라이버를 보여 줍니다. [자주 묻는 질문](FAQ.ko.md)의 해당 항목을 보십시오.

**자동 업데이트 끄기 또는 알림만 받기.** **설정** 탭의 **업데이트** 카드에서 **끄기** 또는 **알림만**을 고르십시오. [자주 묻는 질문](FAQ.ko.md)의 업데이트 항목을 보십시오.

**게임 되돌리기.** **게임** 탭에서 게임을 고르고 **되돌리기**를 누릅니다. 저널(옮기기 전 위치를 적은 기록)에 따라 예전 배치로 복원합니다. 재배치는 파일 내용을 바꾸지 않습니다. 게임이 실행 중이면 되돌리기는 거절됩니다.

**큰 게임 패치 뒤.** 서비스가 스스로 배치를 다시 검사합니다([자주 묻는 질문](FAQ.ko.md) 참고). 직접 다시 하려면 **트레이스 수집**, **계획 만들기**, **재배치 실행**을 다시 합니다.

**제거.** Windows 설치된 앱에서 지웁니다. 데이터 폴더 `%ProgramData%\AsterCache` 는 남으며, 함께 지우려면 `cs_service.ps1 -Action uninstall -PurgeData` 를 실행합니다.

**기록을 다른 PC 로 옮기기.** `aster profile export` 와 `aster profile import` 를 씁니다(아래). 가져올 때는 파일 크기와 표본 해시가 같을 때만 받습니다.

## 직접 하려면(선택)

단계를 직접 다루고 싶거나, 자동 모드가 건너뛴 게임을 시험할 때 씁니다. 관리자 권한으로 **게임** 탭을 열고 아래 버튼을 순서대로 누릅니다.

| 순서 | 버튼 | 하는 일 |
|---|---|---|
| 1 | 등록 | 게임의 exe 파일을 고릅니다. 원본·허용 폴더는 exe 가 있는 폴더로, 볼륨 레이블은 그 드라이브 값으로 채워지며, 예열 트리거 프로그램을 포함해 모든 칸을 고칠 수 있습니다. |
| 2 | 트레이스 수집 | 게임을 실행해 첫 맵까지 로딩하고 끕니다. 읽기 순서를 기록합니다(ETW, 관리자 권한). |
| 3 | 계획 만들기 | 조각을 어디에 둘지 정합니다. 존은 핫 데이터의 1.1배입니다. |
| 4 | 재배치 실행 | 옮길 바이트 수와 되돌릴 수 있다는 안내가 확인 창에 나온 뒤 조각을 옮기며 저널이 남습니다. 한 번에 최대 2 GiB 를 쓰므로 큰 이동은 "다시 실행하면 이어서 합니다" 라고 나올 수 있습니다. |
| 5 | 지금 예열 | 그 존을 바로 RAM 에 올립니다. |
| 6 | 측정 | 존을 한 번 읽는 시간을 잽니다. 읽은 데이터가 파일 캐시에 남으므로 다시 재려면 캐시를 비워야 합니다. |

## `aster` 명령

`aster` 는 관리 창과 같은 작업을 명령으로 실행해 자동화할 수 있게 합니다. 명령마다 `aster <명령> --help` 로 확인하며, 모든 옵션은 [csharp/README.ko.md](../csharp/README.ko.md)에 있습니다.

- `trace --live`, `probe`, `apply --execute`, `revert --execute`, `tier apply|revert|clean` 은 **관리자** PowerShell 에서 실행합니다.
- 출력은 한 줄 JSON 입니다(`aster discover` 는 `--json` 을 붙이지 않으면 글자로 출력합니다). 종료 코드는 0 성공, 1 실행 오류(`{"error": ...}` 한 줄), 2 잘못된 인자, 3 관리자 아님(`{"error":"not_admin"}`), 4 사용 중(다른 실행이 데이터 폴더를 잡고 있음)입니다.
- 전역 옵션은 명령 앞에 둡니다. `--lang ko|en` 은 안내 문구의 언어를 정하고([언어](CONFIGURATION.ko.md#언어) 참고), `--result-file <경로>` 는 출력을 파일에도 씁니다.

| 명령 | 하는 일 |
|---|---|
| `discover [--json]` | 런처 라이브러리에서 찾은 게임 목록을 보여 줍니다. 읽기 전용입니다. |
| `status [--plan <계획>] [--journal <저널>]` | 읽기 전용 현황입니다. 관리자 권한, 디스크, 마지막 예열, 자동 모드를 보여 주며, `--plan` 을 주면 배치 판정도 보여 줍니다. |
| `trace --live --exe <exe> --origin-root <폴더> --out <파일> [--seconds N] [--io-summary-root <폴더>]` | ETW 로 게임이 읽는 내용을 기록합니다. `--io-summary-root` 는 여러 번 지정할 수 있고, 디스크 읽기 완료도 수집해, 세션이 끝난 뒤 그 폴더 아래 파일의 배치(파일 내용이 아님)를 읽어 읽기를 파일에 대응시키고 결과를 `<out>.io.json` 에 저장합니다. `--csv`, `--etl` 은 기존 기록을 변환합니다. |
| `plan --trace <파일> --origin-root <폴더> --zone-mib N --out <파일> [--dry-run]` | 트레이스로 배치 계획을 만듭니다. `--dry-run` 은 수치만 보여 줍니다. |
| `plan estimate --io-summary <파일> [--io-summary <파일> ...] --origin-root <게임 폴더> [--plan <파일>] [--zone-mib 2048,4096,...] [--zone-start-lcn N] [--evaluate-io-summary <파일> ...] [--position-base-ms 6] [--position-full-ms 12] [--transfer-mbps 150] [--session-decay 0.7]` | 지정한 게임 폴더 안의 물리 읽기 집계에서 현재·가상 배치를 추정하며 파일을 옮기지 않습니다. 폴더 밖 집계 파일은 제외하고 건수를 출력합니다. 표준 출력에는 JSON 하나를, 표준 오류에는 짧은 영문 요약을 출력합니다. 같은 `session_id` 는 한 번만 셉니다. `--evaluate-io-summary` 로 준 플레이는 선정에 쓰지 않고 각 선정으로 배치했을 때의 지표만 잽니다. |
| `probe --volume D:` | 재배치 전에 볼륨을 점검합니다. |
| `apply --plan <파일> --allowed-root <폴더> --require-volume-label <레이블> [--dry-run \| --execute]` | 조각을 옮깁니다. `--execute` 가 없으면 아무것도 옮기지 않습니다. 레이블이 다르면 아무것도 건드리지 않습니다. |
| `verify --plan <파일>` | 배치가 그대로 있는지 검사합니다. |
| `revert --journal <파일> --allowed-root <폴더> [--execute]` | 저널로 예전 배치를 복원합니다. |
| `prewarm --plan <파일> --origin-root <폴더>` | 핫 데이터를 존 순서로 RAM 에 읽어 둡니다. `prefetch` 는 같은 명령이며 옵션(`--budget-mib`, `--method`, `--timing`)이 더 있습니다. |
| `launch --game <프로그램 또는 URL> --trace <파일> --origin-root <폴더>` | 게임 실행과 함께 트레이스의 블록을 순서대로 미리 읽는 선읽기를 먼저 시작하고 게임을 켭니다. `--no-prefetch` 는 게임만 켭니다(비교용). |
| `learn --exe <exe> --root <폴더>` | 콘솔에서 실험 기능인 첫 실행 선행 읽기를 합니다(자동 모드에서는 기본 꺼짐). |
| `profile export --game <이름> --out <파일>` / `profile import --file <파일> --game <이름>` | 게임 하나의 기록을 PC 사이에서 주고받습니다. |
| `tier status` / `tier apply --game <이름>` / `tier revert --game <이름>` 또는 `--all` / `tier clean` | 선택 기능인 SSD 보조 저장입니다. |
| `orbit mode off\|shadow\|active` | ORBIT 모드를 정합니다. [ORBIT](ORBIT.ko.md)을 보십시오. |
| `orbit calibrate`, `orbit model`, `orbit-bench run\|rescore\|summarize` | ORBIT 보정과 측정입니다. [ORBIT](ORBIT.ko.md)을 보십시오. |
| `stream-bench` | 선읽기 방식의 읽기 벤치마크입니다. |

## 예시

아래 값은 예시이며 실제 값은 다릅니다.

**런처에서 찾은 게임 목록 보기.** 게임마다 한 줄이며, 이름, 런처, `hdd`·`ssd`·`?`, exe(또는 설치 폴더), 안티치트 표시(없으면 `-`)를 탭으로 나눠 보여 줍니다.

```bat
aster discover
```
```text
Frostpunk	steam	hdd	D:\Games\Frostpunk\Frostpunk.exe	-
```

`--json` 을 붙이면 같은 목록이 `name`, `launcher`, `install_dir`, `exe`, `on_hdd`, `trigger_exe`, `anticheat` 키를 가진 JSON 한 줄로 나옵니다.

**단계를 직접 실행하기.** 첫째, 둘째, 넷째는 관리자 PowerShell 에서 실행합니다.

```bat
aster trace --live --exe Frostpunk.exe --origin-root D:\Games\Frostpunk --out trace.json --seconds 180
aster plan --trace trace.json --origin-root D:\Games\Frostpunk --zone-mib 1536 --out plan.json
aster apply --plan plan.json --allowed-root D:\Games --require-volume-label GAMES --dry-run
aster apply --plan plan.json --allowed-root D:\Games --require-volume-label GAMES --execute
aster prewarm --plan plan.json --origin-root D:\Games\Frostpunk
```

`--zone-mib 1536` 은 예시입니다. 게임의 핫 데이터 크기에 맞춰 정하십시오. 먼저 `--dry-run` 으로 실행하면 아무것도 옮기지 않고 계획만 보여 줍니다.

**관리자 권한 없이 실행하기.** `apply --execute` 는 아무것도 바꾸지 않고 종료 코드 3 으로 끝납니다.

```text
{"error":"not_admin"}
```

**물리 읽기 집계로 재배치 효과를 추정하기.** `--origin-root` 로 준 게임 폴더에 대해 안티치트 표시와 게임 실행 여부를 확인하고, 집계와 선택적 계획 파일, 파일 메타데이터·배치만 조회합니다. 폴더 밖 파일은 집계에서 제외하고 `files_outside_origin_root` 에 셉니다. 게임 파일 내용은 읽지 않고 계획이나 저널도 쓰지 않습니다.

```bat
aster plan estimate --io-summary trace.run14.json.io.json --origin-root D:\Games\Frostpunk --plan plan.json --zone-mib 2048,4096,8192,16384
```

JSON 의 `inputs` 와 `combined` 에 집계별·합친 결과가 들어갑니다. 블록 분류와 사유별 수치, `Order` 의 논리 범위와 블록 겹침으로 낸 계획 커버리지, 존 크기별 현재 물리 조각의 존 포함 여부, 페이징 요청 분류, 블록 안 조각 사이 거리까지 반영한 현재·가상 순서 통계, 지연·요청 수 기준 선정을 포함합니다. 존 포함 여부는 블록의 물리 조각이 모두 존 안에 있을 때만 안으로 셉니다. 선정마다 고른 읽기 바이트와 지연의 비율, 옮길 바이트, 필요한 연속 공간을 냅니다. `files_outside_origin_root` 는 제외한 파일을 중복 없이 셉니다. `current_policy` 는 속성상 이동 가능한 블록과 정책 후보·제외·판정 불가를 나눕니다. 선정 결과의 이동량과 필요한 연속 공간은 마지막 짧은 블록도 클러스터 점유 길이로 셉니다. `--zone-start-lcn` 도 확정된 계획 존도 없으면 LCN 0 을 사용하고 `zone_starts` 에 그 사실을 표시합니다. `zone_starts` 는 볼륨마다 처음 얻은 유효한 배치 조회 결과로 정하고 계획의 존 클러스터 수 `plan_zone_clusters` 도 냅니다. `notes` 에는 존이 시작 위치에서 연속으로 비어 있다고 가정하며 계획이 미리 정해 둔 목표 위치는 존 안으로 세지 않는다는 점을 적습니다. 클러스터가 64 KiB 보다 큰 볼륨의 파일은 `layout_unavailable`(`cluster_larger_than_block`)로 분류합니다. `--origin-root` 는 존재하는 폴더여야 합니다. 정책 제외 목록을 읽지 못하면 `notes` 에 미반영 사실을 표시합니다. 결과는 비교 지표이며 실제 헤드 이동이나 로딩 시간 개선량을 뜻하지 않습니다.

존 크기마다 선정 기준 세 가지(`by_latency`, `by_requests`, `by_link_gain`)를 냅니다. `by_link_gain` 은 블록을 읽기 구간(처음 읽힌 순서에서 이웃하고 디스크 조각도 바로 이어지는 블록의 묶음, 블록 안에서 조각이 끊기면 거기서도 나뉨)으로 묶습니다. 이음은 앞 구간의 끝에서 다음 구간의 시작으로 헤드가 옮겨 가는 한 번의 이동이고, 모형 위치 잡는 시간은 아래 모형으로 계산한 그 이동 시간입니다. 이 기준은 이음으로 줄어드는 모형 위치 잡는 시간이 가장 큰 구간 집합을 존 크기 안에서 고릅니다. 바이트당 값을 정해 한 번 훑는 동적 계획법을 쓰고 그 값은 48회로 정해 둔 이분 탐색으로 정합니다. 고를 수 없는 구간(이동 불가, 세션 중 변경, 정책상 제외, 위치 모름)은 양쪽 이음의 이득이 실현되지 않습니다. `--io-summary` 를 여러 개 주면 최근 것부터 이어 붙이고 이미 나온 블록은 건너뜁니다. 플레이 가중치는 1, `--session-decay`, 그 제곱 … 이고 이음의 가중치는 양쪽 구간 블록 가중치의 평균입니다. 모든 선정과 현재 배치는 `model`(`segments`, `model_position_ms`, `model_transfer_ms`, `links`, 이음 거리의 중앙값과 90 백분위수)을 냅니다. 모형은 0 이 아닌 이음마다 기본 시간 + 추가 시간 × sqrt(min(거리, 디스크 크기) / 디스크 크기) 밀리초(`--position-base-ms` 6, `--position-full-ms` 12)를, 전송에는 바이트 ÷ `--transfer-mbps`(150)를 셉니다. `--transfer-mbps` 가 없으면 데이터 폴더의 `disk_model.json` 에 쓸 수 있는 적합 결과가 있을 때 그 전송률을 씁니다. `link_model.sources` 는 값마다 `defaults`, `arguments`, `calibration` 중 어느 것인지 표시하며 보정 파일은 읽기만 하고 고치거나 새로 측정하지 않습니다. `read_segments` 는 구간 수, 구간 크기 분포, 이음 거리 분포를 냅니다. `evaluation` 은 `--evaluate-io-summary` 플레이마다 각 선정으로 배치했을 때(고른 블록은 존 안 가상 위치, 나머지는 지금 위치)의 같은 `model` 값과 학습에 없던 블록의 비율을 냅니다. 같은 `session_id` 가 `--io-summary` 와 `--evaluate-io-summary` 에 모두 있으면 인자 오류입니다. 세 기준 모두 이동 가능하고 정책상 제외가 아닌 블록만 고릅니다(`candidate_set`). `realized_link_gain_ms`(`by_link_gain` 만)는 선정이 0 으로 만든 이음의 지금 시간 합이며 고르지 않은 이웃과의 이음 변화는 무시합니다. 실제 변화는 `model_position_reduction_ms`(현재 배치의 모형 위치 잡는 시간 − 가상 배치의 값)입니다. `evaluation` 의 선정마다 `link_change` 도 있습니다. `removed`(지금은 0 이 아니고 선정 뒤 0 이 된 이음), `crossing_zone`(한쪽만 존으로 옮겨져 존과 존 밖을 오가며 선정 뒤 0 이 아닌 이음), `inside_zone`(양쪽 모두 존 안인데 0 이 아닌 이음)이고 각각 `links`, `model_position_ms`(선정 뒤), `before_model_position_ms`(같은 이음의 지금 시간)를 냅니다. 모형 시간의 변화는 오가는 이음과 존 안 이음의 (뒤 − 앞) 합에서 없어진 이음의 앞 시간을 뺀 값과 같습니다. 기준 비교에는 구간 수와 모형 시간을 쓰십시오. 이동 거리의 합은 디스크 끝에서 끝으로 가는 이동 몇 번이 좌우하므로 참고로만 남깁니다.

**배치가 그대로인지 검사하기.**


결과에는 검사 내용과 `verdict` 가 들어 있습니다. `contiguous`(제자리), `non-contiguous`(흐트러짐), `resume-needed`(이동이 중단되어 나중에 이어짐) 중 하나입니다.

**전체 상태 보기.** 결과에는 `admin`, `plan`, `journal`, `disks`, `prewarm`, `auto` 키 등이 들어 있습니다(여기서는 줄여서 적었습니다). `prewarm` 은 게임별 마지막 예열, `auto` 는 자동 모드 상태입니다.

```bat
aster status
```
```text
{"admin":true,...,"disks":[...],"prewarm":{...},"auto":{...}}
```
